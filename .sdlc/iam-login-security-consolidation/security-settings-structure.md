# 安全设置菜单与按用户密码策略：需求整理和设计建议
Status: accepted
日期：2026-11-21

## 用户直接明确的调整

- 通用安全与密码策略独立成菜单；密码策略支持不同用户采用不同规则。
- 原风控分级在界面上命名为“MFA策略”，与“多因素认证配置”放入同一菜单，以两个Tab区分。
- 继续参考本轮11张通用安全/密码策略/多因素认证截图，以及上一轮7张个人中心截图；参考信息组织和交互，不照搬第三方品牌、全部功能或示例参数。
- 保持最近决定：IAM接入应用本轮不增加MFA配置。

本文件区分用户已明确的职责与下述待并入实施计划的具体设计。新增按用户密码策略不是现有accepted plan已覆盖的简单拆页；不自行批准新数据模型、代码清单或运行配置变更。

## 菜单与页面

|菜单|页面结构|职责|
|---|---|---|
|通用安全|基础安全、登录防护、人机验证、设备与会话、短信安全、邮件安全等已有能力分区|会话/Remember-me期限、登录限频及失败锁、人机准入、设备规则、公共投递防滥用及账号变更验证|
|密码策略|策略列表与新增/编辑页|默认策略及指定用户策略、强度/历史/有效期/到期提醒、实际生效策略查看|
|多因素认证|严格两个Tab：MFA策略、多因素认证配置|策略回答何时补验及要求；因素配置回答提供哪些方式及参数|

### MFA策略Tab

- 收拢原风险信号权重、分级阈值、LOW/MEDIUM/HIGH处置，展示固定等级、条件、动作、允许因素、最低强度、证据窗口、环境变化和风险升高后的复核要求。
- 等级处置仍是允许、要求认证或拒绝；界面改名不把原BLOCK误解释成“验证一个MFA后一定可登录”。账号禁用、人工锁、明确业务拒绝和敏感接口要求仍生效。
- 登录失败限制本身归通用安全；MFA策略仅引用失败信号及其评分，不再建立第二份限频/锁号计数。IP归属地供应商状态与诊断可放在相关策略区块内，沿用现有权限及唯一配置源。
- 平台风险处置与租户评分原有授权边界保留；合并同页不合并写权限。只读/保存权限按真实分区控制，不允许普通租户评分权限修改平台因素或处置。
- 风险评估技术职责及原完整PolicyEvaluationContext、提交围栏保留；UI改名不必机械重命名所有Risk领域类型/API。

### 多因素认证配置Tab

- 卡片展示SMS、EMAIL、TOTP和PASSKEY的启用状态、实际配置/设施就绪状态及因素参数；详细配置就地展开或弹窗，保持仅两个顶层Tab。
- 短信/邮件展示固定SMS_LOGIN/MAIL_LOGIN关联、有效参数及原消息管理入口，不复制供应商秘密。TOTP显示验证器参数/部署就绪；Passkey显示UV要求、RP/Origin可信状态及个人管理入口。
- 不在这里再放一套强制/自适应触发开关，不恢复旧全局MFA JSON或旧模式。用户在已启用、适用、本次策略允许、本人已绑定且实际可用的独立因素交集中选择。
- 个人中心继续采用统一卡片/向导，手机号邮箱复用账号绑定，Passkey列表/详情共用唯一凭据管理。指纹和面容作为设备Passkey验证体验呈现，不新增独立人脸/指纹因素。

## 密码策略设计建议

### 策略与用户

- 提供一套明确的默认密码策略，以及可命名的指定用户策略。按参考图支持通过已有授权目录搜索并选择多个具体用户；本轮不擅自扩展部门/角色/组织继承。
- 建议解析优先级：指定用户的有效策略优先，未指定时使用所属受管范围的默认策略。不能将不同用户的规则混合，也不能依保存顺序随机选择。
- 同一密码凭据主体最多关联一套有效指定策略；重复分配在保存时明确冲突，不静默覆盖。用户详情和预览显示实际策略名称、来源与版本。
- 默认策略不能在没有有效替代的情况下删除/停用；停用/移除指定策略需预览将回到的默认策略，不静默变成无规则。
- “不同用户”是管理员指定策略，个人用户不能在个人中心选择更宽松的密码规则。个人中心只展示适用要求和修改入口。

### 列表和表单

- 列表展示名称、默认/指定用户范围、启用状态、规则摘要、更新时间及操作；支持查看适用用户及实际影响，不把联系方式全量回显。
- 新增/编辑页参考截图分组：基础信息、策略应用主体、密码强度、密码历史/有效期及到期提醒；显示参数单位与校验错误，保存/取消和加载/失败状态明确。
- 首先复用现有已实现的最小/最大长度、复杂度、弱密码/账号信息/重复或连续字符限制、历史次数、有效天数及提前提醒规则；不从截图自动引入任意正则、明文密码检测接口、无校验密码、35位上限、短信提醒或账号注销等新增能力。
- 注册/设置初始密码、后台设置/重置、个人改密、忘记密码恢复及到期判断必须使用同一有效策略解析器与服务端校验，不能仅前端按人区分，而IAM仍读取原租户字典。
- 策略改变不重写密码哈希，不伪造已知当前密码强度。是否要求已有账号下次完成受限改密由明确规则决定，不可直接将策略变化当作密码错误。
- 密码和测试密码不进入日志、URL参数、审计正文或策略文档；保留既有安全版本推进、凭据撤销、密码历史及人工锁保护。

## 需要在具体实施计划解决的边界

- blocking：当前IAM/System密码校验与登录到期判断按租户字典读取，新增按用户的持久化、分配、版本/CAS、权限和唯一解析器须列入修订后的文件清单及评审；仅拆菜单不能宣称需求完成。
- blocking：当前本地employee密码是sys_user凭据，多个IAM租户安全身份可能共享同一账号密码。指定策略须以真实凭据主体为基础并保留租户/目录授权隔离，不能让某次请求选择租户后放宽共享密码要求，也不能因同号userId修改外部目录密码；默认策略的归属及共享账号规则冲突须在实现前明确。
- non-blocking：截图中未实现的App验证、IP互斥/白名单、自定义报错、恢复代码、通知渠道、注销及正则规则只作为参考，不在本轮顺带添加开关或空实现。
- non-blocking：两个MFA Tab保留既有分区草稿CAS/预览/启用语义；Tab切换不丢未保存输入，分区保存以最新草稿合并，不能互相覆盖。

## 验证要求

1. 菜单/路由/i18n/权限一致，旧通用安全页不重复密码表单或风险分级；多因素认证恰有两个规定Tab。
2. 用户A、用户B明确指定不同策略，另一个用户走默认；所有改密/重置/到期入口得到相同解析结果。
3. 重复绑定冲突、指定策略停用后的默认回落、无默认拒绝、跨租户/跨目录同号及共享本地凭据边界均有允许/拒绝证据；策略与分配并发变更不能用旧规则提交新密码。
4. MFA分区权限隔离、并发保存、Tab切换/取消/加载/错误恢复、因素真实可用性、Passkey证据复用和空交集拒绝沿用原验证要求。
5. 实际业务源代码及数据库/菜单迁移须在具体修订计划获批后实施；真实迁移、配置启用、镜像和容器切换仍未获本次设计讨论授权。


产品方向确认：用户于2026-11-21明确回复“对的”，接受上述三个菜单、MFA两个Tab及默认/指定用户密码策略方向。具体凭据归属、统一默认初始化、权限、接口/数据结构、锁序与文件清单见[security-settings-plan.md](security-settings-plan.md)，该工程计划仍为draft并等待独立审查/批准；本条不将尚未展示的工程决定自批。
