# Intent: 登录安全收敛与认证能力完善
Author: 用户. Status: accepted.

## Problem
登录安全、MFA、设备与会话存在重复规则、新旧配置并存及部分配置未实际执行的问题。人机验证和IP归属地查询缺少完整配置界面；现有登录方式缺少WebAuthn/Passkey抗钓鱼认证。目标是减少攻击成功机会并保持正常用户可登录、可恢复，不能以增加验证步骤代替有效安全控制。

## Proposed outcome
1. 落实已同意的安全收敛：统一限频和设备配额的权威来源，补齐未生效配置，调整风险软信号触发永久锁号的行为，阻止同一因素重复验证被误算为MFA；保留登录、令牌发布与敏感访问必要的状态复核。
2. 保留本地人机验证，完整接入腾讯云供选择。本地交互参考腾讯的加载、验证、取消、重试、过期和移动端体验，不宣称复制其商业反机器人能力。密码、发码、MFA、恢复与绑定等适用场景统一闭环，服务器核验及一次性绑定不可绕过。
3. 补齐人机验证管理界面：供应商公开参数、秘密配置、触发策略、可用性测试、保存结果及故障提示。秘密不回显、不进入日志；缺少配置不能被误显示为可用。
4. 补齐现有IPDataCloud配置界面与诊断：显示配置状态，区分未配置、超时、查询失败、未知归属地及正常结果；未知位置不能直接等同攻击。管理员测试不能演变为任意URL代理。
5. WebAuthn/Passkey支持无密码登录、MFA及敏感操作补认证；个人安全中心提供注册、查看、命名和撤销。满足服务器验证的用户验证强度、有效期及环境要求后复用同一认证证据，避免无意义追加短信。
6. Passkey注册、撤销和恢复具有身份复核、授权与审计；恢复入口不能绕过既定强认证，不能因删除最后凭据锁死用户。管理员启用强制策略前能识别不可用因素和自身被锁风险。
7. 每个开放配置项均有实际允许、拒绝、失效和恢复证据；区分模拟、真实基础设施、浏览器和真实供应商验证，不把页面保存或构建成功当作安全验收。

## Affected users and systems
平台安全管理员、已有用户和应用接入方；Cloud IAM/System/System API/Admin，以及必要的Boot Gateway MFA契约。供应商基础设施配置按平台权限管理；保留现有租户防护和平台统一MFA边界。

## Constraints
保持Java17及Spring Security扩展体系，优先使用官方WebAuthn能力；不自写密码学、不重写框架安全链。WebAuthn/Passkey不改变既有资源授权注解@Passkey的合同。

保留未提交工作、真实凭据、密码哈希、账号/应用/外部身份绑定。供应商秘密需受保护存储，不能以明文写进普通策略字典或回显浏览器；不擅自轮换秘密、启用真实云服务或更改现有安全策略。

RP ID与允许Origin必须明确可信，不能从任意Host/转发头推导。正式域名未确认前，不登记或部署生产Passkey凭据。本轮不自动推送、合并或发布远端。
