# Intent: IAM 登录风险、在线会话与安全策略执行
Author: Rain. Status: accepted.

## Problem
现有安全策略已提供配置管理，但尚未完整落实到 IAM 登录和会话运行时；MFA 只有检查扩展点。管理员需要在 IAM 正式上线前具备在线用户查询、登录审计、风险处置和全部接入资源服务器同步踢出能力。

## Proposed outcome
- 在线会话管理支持按 token 或用户名查找，展示用户、登录时间、IP、UA、设备信息、认证方式、实际签发 client_id、风险等级及原因；支持禁用、踢出、启用 MFA 和账户锁定管理。
- 登录日志明确保存 IP、UA、设备信息、client_id、风险判定及登录/MFA 结果，默认保存三个月；管理操作和撤销同步结果可审计。未签发 token 的记录明确标记，不伪造签发信息。
- 采用可配置的失败次数/频率、陌生设备、异常 IP 和异地登录风险信号及分级阈值。每次登录先完成风险判定：低风险在其他认证与安全策略通过后允许签发；中风险必须通过邮箱或短信验证码 MFA；高风险拒绝登录并锁定账户。
- 高风险锁定立即撤销该账户全部会话、access token 和 refresh token，只允许管理员解锁，不能被自动解锁策略解除。
- 踢出在 IAM 撤销目标用户全部 token，并回调全部已接入的资源服务器，尽力使其拒绝已撤销凭据；用户补充接受资源服务器短暂不一致，不要求全局瞬时完成。资源服务器包括网关，通过统一回调接口接入，参考 Macula Boot 现有网关 token 清理接口。
- 落实既有通用安全、防御和密码策略，形成可验证的运行时行为。

## Affected users and systems
登录用户、安全管理员、租户管理员及授权 ROOT 管理员；Macula Cloud IAM、System、System API、Gateway、Admin，所有已接入资源服务器，以及必要的 Macula Boot Gateway Starter 通用能力。

## Constraints
- 风险检查全覆盖，包括普通登录、第三方登录、端内登录、SSO 复用及 token 刷新；无用户的 client_credentials 不受本次用户风险规则限制，保留其原有客户端认证与授权要求。
- MFA 使用已绑定手机短信或邮箱二选一，不强制跨通道；账户启用 MFA 后，即使判定为低风险也必须通过已绑定邮箱或手机号完成 MFA。中风险同样必须通过 MFA。邮箱和手机号均未绑定时拒绝登录，不允许通过未绑定的临时收件地址或手机号绕过。未完成所需 MFA 不得获得可用业务会话或 token。
- 禁用、锁定、踢出和启用 MFA 必须有权限校验，用户、日志、会话及管理操作遵守既有租户隔离边界。高风险锁定需防止恶意锁号；管理员解锁不恢复已撤销凭据。
- IP 地理数据通过可配置的开放 IP 地理地址查询接口获取，首期按用户指定的 IPDataCloud IP 归属地文档接入（https://www.ipdatacloud.com/doc/ipguishudi/），用于异地登录判定；IP 来源必须明确且可信，异地判定不得仅信任客户端声明；UA 和设备信息作为风险线索，不能代替可信身份。token 查询不能造成完整 token 在日志、URL 或列表中泄露。
- 全部已接入资源服务器都须纳入撤销回调与结果追踪；失败或超时不得显示为同步完成，并须支持重试和补偿。不得通过 refresh token 或 SSO 恢复已撤销访问；资源服务器缓存允许有限期不一致，但不得无限续期已撤销访问。
- 通用策略覆盖会话、验证码、记住登录有效期和最大会话数；防御策略覆盖失败窗口、失败次数、自动解锁及 CSP，但高风险锁定仅允许管理员解除；密码策略覆盖长度、复杂度、弱密码、账号包含、重复字符、历史密码、连续序列、有效期及到期提醒。
- IAM 尚未正式上线，无存量密码迁移要求，密码统一按新策略执行；保留现有应用、客户端凭据、身份源和身份绑定，不擅自清理其他数据。
- 登录审计明确记录 IP、UA 和设备信息，但不记录密码、完整 token 或验证码。日志默认保存三个月并清理到期数据。
- 本 intent 已由用户明确接受；spec 和 plan 仍须分别经人工接受后再修改源码。

## Open questions
- 首期供应商已指定为 IPDataCloud；设计明确其接口契约与配置方式、地域粒度、基线、具体阈值，以及代理、内网、查询失败和定位未知时的处理；真实产品密钥与所购产品字段留待部署前联调。
- 设计阶段明确 MFA 启用粒度、已绑定短信/邮箱之间的选择、验证码防重放与限流及恢复流程；恢复流程不得绕过未绑定时拒绝登录的约束。明确“禁用”的操作对象及其与锁定、启用的关系。
- 设计阶段明确资源服务器注册与实例范围、回调认证及防重放、幂等、同步时限、失败补偿和不可达时的访问处理；现有 Macula Boot 接口目前按单个 token 清理缓存，须验证全量撤销契约。
- 设计阶段明确三个月的日历口径、清理时点、在线会话判定，以及会话、验证码和客户端 token 有效期之间的关系。
