## Risks
- Creating `6.0.x` at the wrong commit would contaminate the maintenance line. The operation is ordered first and guarded by exact local and remote SHA checks; no force push is planned.
- Boot `4.0.8` is newer than the `4.0.2` version recorded in the Cloud `2025.1.1` BOM metadata. Maven convergence, focused tests, and full Stage 4 verification must demonstrate compatibility; any need to change the accepted platform versions returns to the reviewer.
- Boot 4, Framework 7, Jackson 3, and Gateway 5 can change Java types, auto-configuration behavior, serialization, and reactive APIs. Changes stay within compiler- or test-proven compatibility scope, and user-visible differences require migration notes and regression tests.
- Alibaba 2025.1 removes the old bootstrap configuration path. An incomplete move to Config Data imports can make applications start without remote configuration or use the wrong namespace. Runtime smoke checks must prove configuration is loaded from the intended source.
- Other managed libraries may not yet support Boot 4 or Jackson 3. Compatible upgrades can be proposed only when needed for the accepted migration; removing a feature, downgrading the accepted platform, or making an unrelated dependency sweep invalidates the plan and requires human direction.
- Existing downstream users may depend on Boot 3-era public types or serialized output. Preserve APIs and wire behavior where upstream permits; document unavoidable source or behavior changes as 6.1 migration requirements.
- Docker and external Nacos, Polaris, Redis, databases, or cloud services may be unavailable locally. Environment failures are reported separately and cannot be converted into a healthy result.
- Pushing the new branch does not guarantee GitHub protection rules cover it. Branch-protection configuration remains a separate repository-administration concern.
- Rollback keeps `6.0.x` fixed at the pre-upgrade commit and reverts discrete 6.1 commits on `main`; it does not use `release.sh`, destructive resets, tags, or production deployment.
