# 测试与验证

编写测试或决定验证范围时加载。

## 测试策略

- 修复缺陷先添加能复现问题的测试；新行为同时覆盖正常路径和关键边界。
- 纯逻辑优先使用单元测试；自动配置优先使用轻量 Spring 上下文测试；只有真实集成必要时才启动完整应用。
- 沿用目标模块现有的 JUnit、Mockito、Spring Test 与断言风格，不为单个改动引入新的测试框架。
- 测试应可重复、与执行顺序无关；避免真实时间、随机值、网络或共享外部状态造成不稳定。

## 验证顺序

1. 单个测试方法或测试类。
2. `mvn -pl <module-path> -am test`。
3. 跨模块或父 POM 变更后运行 `mvn test`。
4. 影响打包、revision 或发布配置时，再运行 deploy profile 完整构建。

## 环境依赖

- Redis、Kafka、RocketMQ、数据库和云服务测试可能要求本地服务或凭据；运行前查看测试的 `application.yml` 与 README。
- 无法满足外部条件时，报告未运行项、所需条件和已经完成的替代验证，不要静默跳过。
- 最终说明实际执行的命令、结果以及任何未验证范围。
